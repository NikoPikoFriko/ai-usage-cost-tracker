## Upgrade notes

Existing local databases are migrated in place when `TrackerDB` opens them. The migration adds `grain` and `money_rail`, creates a rail index, backfills Codex rows to `grain=turn`, and assigns `credits` unless `billing_identity=api_org`, which maps to `api_metered`. Operators should back up `data/tracker.db` before first v0.2.0 use because the project does not yet provide a downgrade migration.

After pulling the release, operators should reinstall dependencies, run the normal ingest, and regenerate the web export. Existing idempotent event IDs remain in use. The pricing and alias CSVs are repository resources in this release; clean-wheel packaging remains I9 and is not promised by v0.2.0.
